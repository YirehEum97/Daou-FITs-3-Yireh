## Dependency Injection
외부에서 두 객체간의 관계를 정해주는 디자인 패턴
이를 통해 클래스 간의 관계가 느슨해져 확장성과 유지보수에 유리하며 상속의 제약을 피할 수 있다.
### step1
일반적인 DAO
### step2
중복된 code를 method로 분리해 class의 유지보수성을 올림
### step3
추상 method와 추상 class로 만들어서 제공
상위 class에서 기본적인 logic의 흐름을 구현하고 하위 class에서 구체적인 구현 내용을 변경해서 구형
상속은 Java의 단일 클래스 상속 한계로 인해 사용이 불가능한 경우가 있음
### step4
UserDAO 재사용을 위해 UserDAO에 명시적으로 정해진 class를 만들어서 사용
이를 통해 객체를 받아 사용하기 때문에 단일 상속의 한계로부터 자유로움
다만 지정된 class의 명에 따라 만들어야한다는 한계점을 가짐
### step5
interface를 제공해 단일 상속의 한계의 영향을 받지 않고 interface를 사용한 객체를 전달해서 사용할 수 있음
다만 아직은 객체 생성 단계에서 지정된 class명을 사용해야함
### step6
객체를 직접 생성하지 않고 interface로 구현 된 객체를 전달받아 객체의 method를 사용하는 방식으로 구현
이 방식을 사용하면 class명명이 자유로우며 프로그램 변화가 있을 때 interface로 구현이 된 class를
새로 만들어서 사용하면 되기 때문에 기존의 코드를 크게 수정할 필요가 없다.
